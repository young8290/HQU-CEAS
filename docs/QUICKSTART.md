# 快速上手(QUICKSTART)

第一次接触本系统,按你的身份直接跳到对应小节。每一步都写明**在哪个侧边栏分组、点哪个菜单、对应哪个页面路径**。登录后系统也内置同样内容的「新手指引」页(平台分组 → 新手指引,`/guide`),并在每页顶部提供「操作指南」PDF。

- [我是学院管理员](#管理员第一次使用怎么走)
- [我是班长](#班长第一次使用怎么走)
- [我是审核小组成员](#审核成员第一次使用怎么走)
- [我是维护者/开发者](#维护者10-分钟跑起来)

侧边栏分为三组:**综测系统**、**申报系统**、**平台**。看不到某个菜单说明你的角色没有该权限,属正常现象。

## 管理员:第一次使用怎么走

从建学年到导出材料的完整链路,按顺序做完即可开学期。

| 步骤 | 去哪点 | 做什么 |
| --- | --- | --- |
| 1. 创建学年并开放系统 | 平台 → **系统设置**(`/settings`) | 创建当前学年并「设为当前」;勾选开放综测系统/申报系统入口 |
| 2. 导入学生名单 | 综测系统 → **学生管理**(`/evaluation/students`) | 先「下载模板」,填好后一次性导入全院学生;表中缺失的年级、班级会自动补建 |
| 3. 生成并分发班长账号 | 平台 → **账号管理**(`/accounts`) | 点「批量生成班长账号」;再「导出账号表格」(含初始密码)线下分发,或配置邮箱后直接发送账号邮件 |
| 4. 导入学业与体育成绩 | 综测系统 → **数据导入**(`/evaluation/import`) | 分别导入教务学业成绩表、体测/体育课成绩表;失败明细可在导入日志与「附件导出」页下载 |
| 5. 跟进综测进度并导出附件 | 综测系统 → **综测总览**(`/evaluation/dashboard`)、**分数管理**(`/evaluation/scores`);完成后 → **附件导出**(`/evaluation/export`) | 查看各班填报与审核情况;导出附件 2/附件 4,或按年级打包全部班级 |
| 6. 申报期:导入名额并审核申报 | 申报系统 → **申报数据导入**(`/declaration/import`);班长提交后 → **申报审核**(`/declaration/reviews`) | 导入外部奖项名单、院奖名额金额(以及先进班级名单、班长邮箱);对每个申报批次核对协议 PDF 后「退回修改」或「确认通过」 |

**更进一步**(需要时再看,详见 [USER_GUIDE.md](USER_GUIDE.md)):国家奖学金评比单元与分层评定(申报系统 → 国家奖学金,`/declaration/national-scholarship`)、申报材料导出(`/declaration/export`)、邮箱配置与邮件模板(平台 → 邮箱配置/邮件模板)、操作日志(平台 → 操作日志)。

## 班长:第一次使用怎么走

用管理员发放的账号在 `/login` 登录后,按顺序完成本班综测与申报。

| 步骤 | 去哪点 | 做什么 |
| --- | --- | --- |
| 1. 修改初始密码 | 平台 → **系统设置**(`/settings`) | 用初始密码换成自己的密码,核对账号信息 |
| 2. 填写本班综测分数 | 综测系统 → **本班综测**(`/evaluation/class/scores`) | 选择本班进入分数编辑,逐项填写;用「明」按钮登记每项的加/减分明细;输入后自动保存。也可在 综测系统 → **数据导入**(`/evaluation/import`)批量导入「个人综测填写表」补分 |
| 3. 组建审核小组并核对签名 | 综测系统 → **审核小组确认**(`/evaluation/class/review`) | 添加小组成员(默认班长/团支书/学习委员三类,可改),为每人生成专属审核链接发给对方;成员核对完成后采集签名,全员签名后自动生成本班审核确认书 PDF |
| 4. 申报期:提交奖学金与荣誉称号 | 申报系统 → **申报数据导入**(`/declaration/import`)→ **奖学金申报**(`/declaration/class/awards`)、**荣誉称号**(`/declaration/class/honors`) | 先导入本班申报补充信息(性别/处分/任职/竞赛/申报意愿等);再勾选符合条件的名单、逐项完成确认事项、在线签名后提交 |
| 5. 跟踪提交记录与退回意见 | 申报系统 → **提交记录**(`/declaration/class/submissions`) | 查看每个批次的审核状态;被退回时按审核意见修改后重新提交 |

> 提交奖学金/荣誉称号的前提:本班综测审核(第 3 步)已完成并生成确认书 PDF,且申报系统处于开放状态。候选条件、名额金额等规则见 [BUSINESS.md](BUSINESS.md)。

## 审核成员:第一次使用怎么走

无需注册账号,凭班长发来的专属链接参与本班综测核对。

| 步骤 | 做什么 |
| --- | --- |
| 1. 打开班长发来的审核链接 | 链接自动完成身份校验并绑定当前设备(换设备需班长重新生成链接),直接进入本班综测核对页(`/review/scores`) |
| 2. 逐个核对学生分数 | 查看每位学生各项分数与加分明细,对每人标记「已核对」或「有异议」(异议需填写说明);核对状态实时同步到班长端 |
| 3. 完成核对后签名确认 | 在页面底部「本人签名」手写签名或上传签名图片;全组签名后本班审核确认书自动更新 |

## 维护者:10 分钟跑起来

环境要求:Node.js 18+、npm 9+。

```bash
git clone <repository-url>
cd HQU-CEAS
npm install

# 可选:创建后端 .env(本地开发可跳过——缺 JWT_SECRET 时仅告警并用开发默认值;生产必须配置)
cp packages/backend/.env.example packages/backend/.env

npm run db:generate   # 生成 Prisma Client
npm run dev           # 并发启动后端(4000)与前端(3000)
```

验证与说明:

| 检查点 | 说明 |
| --- | --- |
| `http://localhost:4000/api/health` | 返回 `{ status: 'ok', version, uptime }` 即后端正常 |
| `http://localhost:3000` | 自动跳转登录页;开发模式 Vite 将 `/api` 与 `/ws` 代理到 4000 |
| 数据库 | 随库携带干净种子库 `packages/backend/prisma/dev.db`(默认管理员 `admin / admin123`,登录后请改密),克隆即用;需重建:删 `dev.db` 后 `npm run db:push && npm run db:seed` |
| `npm test` | 后端 76 个用例(node:test),全绿说明业务规则未被破坏 |
